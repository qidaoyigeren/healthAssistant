# Harness P4 状态核查

核查日期：2026-09-07。状态：**条件未触发，未实施、未做生产部署验收**。

现有项目仍以 SQLite、单写者 worker 和 local-demo 患者范围为基线。当前任务是检查 Harness 改造并补齐本地最终验收，没有给出生产患者数、事件并发、可用性、RPO/RTO 目标，也没有要求 PostgreSQL 或多患者上线。本轮未迁移正式数据、启动生产 worker 或把演示身份机制声明为多用户认证。

P4 Prompt 明确要求先核查触发条件，因此不会把未启动的分布式部署改造计为“已通过”。本地线程、临时 SQLite、模拟进程崩溃和合成延迟均不能替代 P4 的真实 PostgreSQL + 至少两个独立 worker 验收。

## 后续设计边界

保留模块化单体，用 API 受理、事务 outbox、独立 worker、PostgreSQL 和兼容 checkpointer 构成最小部署。可信身份负责解析 tenant/patient scope，scope 必须进入领域查询、唯一键和资源访问门，不能只在 REST 层过滤。

领域事务与 checkpoint 事务继续分开建模；即使二者同在 PostgreSQL，也需保留操作回执、lease fencing 和核对恢复。默认采用维护窗口、备份校验、显式切换和可演练回滚；没有双写需求时不增加影子写入。迁移前后都保留旧事实版本、冲突和审核依据。

正式启动时应交付 deployment.md、migration.md、rollback.md、restore-drill.md 及实测报告。上述内容是设计边界与待验收清单，不是本轮已经执行的部署操作。
