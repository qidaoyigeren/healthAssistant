## 修复的实质问题

1. **幂等键曾遗漏业务内容。** 创建相同键但不同目标、补充相同键但不同记录，过去可能误放回旧回执。现在摘要包含目标、修订号和补充内容，重复提交可重放，异内容复用键会拒绝。
2. **补充记录曾部分提交。** 先写药单、后遇到非法语义字段时，内层提交使药单残留。改为共享事务内方法，并验证结构、允许字段和非空值；回归证明后续输入失败会整体回滚。补充保留已有剂量、频次、途径和成分。
3. **开放核查曾在请求/事务中执行。** 接收时原子保存任务、运行记录、预算预留和队列项；模型与工具 I/O 在事务外执行。现有 worker 的租约、心跳和失败机制负责派发；结果、任务状态与队列完成原子发布。发布前复验患者版本，取消优先于迟到结果。
4. **跨轮预算和恢复不完整。** 在派发前预留任务调用/token 额度，恢复已存的调查状态及周期计数；完成结果可复用。恢复不会重新获得一份免费预算。收尾预留仅作用于 investigation，避免破坏旧流程。
5. **熔断曾阻止安全兜底继续核查。** 禁用错误规划器后，确定性工具可完成剩余证据读取；最终保留模型降级事实。新增报告层修复：即使未触发熔断，provider_error 兜底也显示 degraded，目标仍可 completed。
6. **患者记录存在曾被误当作条件适用。** 记录一个肾功能数值不能证明材料的临床适用条件。条件性证据保持不足；无条件来源可以独立支持同一有界 claim。并未增加自动临床判断。
7. **等待审核曾缺少实际队列衔接。** 开启现有模拟审核时，证据冲突进入真实本地审核队列；补充要求可恢复为 waiting_input；过期患者版本拒绝旧决策。该路径不允许把证据不完整直接审批成已解决。
8. **多 Agent 曾只有确定性包装。** 新增 `stage0/harness/model_review.py`：两个固定只读角色、每角色最多 4 次决策、最多 8 个 claim、共享最多 60 秒和父任务预算；证据必须实际回读并通过父级校验，禁止写入、审批和递归派发。未派发、超时、不完整与分歧均显式保留。
9. **前端收尾。** 排队中显示进度并轮询，避免再次继续；部分报告取最新版本，支持原文回读；未完成的协作不能显示为「无分歧」；审核明确为模拟服务。

## 真实模型结果：任务成功不等于规划成功

预先固定 k=3，官方智谱 `glm-4.7-flash`，每次最多 180 秒 / 8 次调用，单个已暴露的合成开发任务，固定检索材料。没有将真实用户数据发给模型，没有增加重试直到通过。

| 原始在线样本 | 耗时 | 尝试 / 实际返回 / usage 未知 | 已知 token | 任务 rubric | 未经兜底的自主规划 |
|---|---:|---|---:|---|---|
| [1](live-final-1.json) | 25.08 秒 | 5 / 2 / 3 | 8,320 | 通过 | 失败：限流与两次提前结束提案被拒绝，熔断后规则完成 |
| [2](live-final-2.json) | 29.57 秒 | 3 / 2 / 1 | 6,322 | 通过 | 失败：限流与两次提案被拒绝，熔断后规则完成 |
| [3](live-final-3.json) | 39.16 秒 | 5 / 1 / 4 | 3,065 | 通过 | 失败：模型提案被拒绝，其余 provider_error 由规则兜底 |

合计 13 次尝试、5 次实际模型返回、8 次 usage 未知，已知 token 17,707。未知消耗不按零计费推断。三次中没有被接受执行的模型提案，所以自主规划为 0/3；有界报告都是模板输出，`llm_answer_success=false` 保持原值。这批结果证明了失败时的确定性恢复，不能证明当前免费模型的自主规划质量。

三次在线记录采样期间代码未变，见 [live-cohort.json](live-cohort.json)。随后修复了 provider 兜底的**报告状态**，最终工程指纹为 `7871ac2fc4d769ae7fb6911e4cb1617f370bb8982f048a525316996f5f435d9b`（Python + 前端）；最终 Python 指纹为 `6b9dcdb5b76c152715cbacaf5acc2fd06ca49c3521759e1027ba339ccf56a495`。原线上样本的 Python 指纹为 `a0519ef208e7ec4c4233ccbcef2e35fcb98d10cf56a24b62b2ad2e1112cc4527`。最终源码只做零调用回放验证，未把旧线上记录伪装成最终指纹的新在线结果。

## 使用与复现

原有确定性双角色复核默认开启，仅在触发条件满足时运行，`AGENT_MULTI_REVIEW_ENABLED=0` 可关闭。真实模型 worker 另需 `AGENT_MULTI_REVIEW_MODEL_ENABLED=1`、父规划器显式启用及模型配置；默认关闭。复核结果是附加证据数据，不自动改写患者结论。

```powershell
# 使用新的目录，脚本拒绝覆盖已有验收。
.venv/Scripts/python.exe scripts/verify-agent-closeout.py --out output/agent-acceptance-next

# 不访问远程模型，复用已记录的提案与 provider 错误。
.venv/Scripts/python.exe scripts/replay-agent-closeout.py --directory docs/agent-capability-upgrade/closeout-2026-09-10 --out output/agent-recorded-replay-next.json

# 隔离合成服务供手动浏览；前端代理目标设为此端口。
.venv/Scripts/python.exe -m stage0.agent_closeout_fixture --directory output/agent-browser-next --port 8039
```

仍未完成的效果验收是：稳定模型上的规划质量、A4 单 Agent / 确定性双角色 / 真实模型双角色的公平比较，以及独立采集且封存的盲测。现有证据不足以替这些项目打勾；当前可交付亮点是**可恢复的长任务、可验证的证据回读、共享预算与如实报告降级的执行机制**。
