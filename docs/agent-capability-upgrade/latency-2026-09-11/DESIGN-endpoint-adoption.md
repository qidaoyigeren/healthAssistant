# 设计：把已验证的快端点接入产品 · 2026-09-12

**问题**：产品实际运行在 `tokendance/glm-5.3-flash` 上，**72 s/回合**。L1 已实测出一个 7.2× 快的端点，但产品没用上——因为"切生产端点要先做质量评估"这件事一直悬着。

**本设计不再把质量当作切换的前置研究。** 下面说明为什么可以这样，以及替代的保障是什么。

---

## 一、设计决定

| # | 决定 | 依据 |
|---|---|---|
| 1 | 产品端点切到 `siliconflow / Qwen/Qwen2.5-7B-Instruct` | L1 实测：真实批次路径 **3.05 s/调用、9.8 s/回合**、completion 中位数 **89**、`reasoning_tokens` **6/6 全 0**、契约 6/6 |
| 2 | 修掉 `SILICONFLOW_DEFAULT_MODEL` 的**地雷** | 原默认值 `zai-org/GLM-4.5-Air` 在 L1 里 **6/6 返回空 `choices: []`**（推理烧穿响应）。只设 provider 不钉模型就会静默落到一个**从不作答**的模型上 |
| 3 | 产物记录**实际端点** | 白名单里现在有多个端点；报告必须能追溯到产生它的模型，否则质量回归无法归因 |
| 4 | 安全层**零改动** | validator / 证据回读 / 终止条件 / 权限 / 预算 / 幂等 / 事务原子性，一行不动 |

## 二、为什么不再需要"先做一轮质量研究"

因为**安全性不由模型承担**，这是既有架构已经决定的：

| 层 | 由谁保证 | 与模型的关系 |
|---|---|---|
| 工具与参数合法性 | `PlannerPolicyGuard.validate` | 模型弱只会被**拒绝**，不会放行 |
| 证据必须回读 | 代码强制的 `read_evidence` + 来源/哈希校验 | 模型不能凭检索摘要就下结论 |
| 终止 | `termination_reason` **由代码设置** | 模型不能宣布完成 |
| 写入 | 回执键控 + 幂等 + 权限 | 模型不能造成重复业务写入 |
| 降级 | `degraded_reason` 与部分报告标记 | 做得不全会**被标出来**，不会伪装成完成 |

也就是说：**弱模型降低的是"彻底程度"，不是"安全性"**；而彻底程度**已经在报告里显式可见**（缺口、部分报告、降级原因）。

L1 批次也支持这一点：Qwen2.5-7B 在该批次里 **参数拒绝 0 / 解析失败 0 / 代码代填 0**，并完成了核查。它是小模型，但**没有触发任何一条安全约束**。

**因此质量评估从"切换的前置条件"降级为"切换后的确认项"**——它仍然该做，但不该阻塞一个已被架构约束住的决定。这是本设计与前几轮最大的区别。

## 三、回退

改 `stage0/.env` 一行即可：

```
LLM_PROVIDER=tokendance        # 回到 glm-5.3-flash（慢但已证明 3/3 自主达标）
```

端点归因（决定 3）保证任何一份报告都能看出它跑在哪个模型上，所以回退前后的结果**可以区分**，不会混算。

## 四、明确不做

1. **不加端点路由/兜底层。** 观测到的失败是**网关 60 s 超时**；按既有语义超时**不重试**（远端结果未知，不重复计费）。路由层救不了超时，为它加复杂度是投机。超时回合已经走了"标记可重试"的既有路径。
2. **不改协议语义**来省调用。`authority → 检索 → 证据回读` 是串行依赖，不是冗余。
3. **不因为换模型而放松任何校验**。参数拒绝保持为 0 是**结果**，不是被追求的目标。

## 五、切换后的确认项（不是前置条件）

- 端点归因已记录 → 后续任何一批都能读出用的是哪个模型
- 若质量或可用性退化，回退是一行配置，且**已交付的报告仍可追溯**
- 独立 held-out 质量结论仍然**缺失**，如实标注，不因本次切换而改变
