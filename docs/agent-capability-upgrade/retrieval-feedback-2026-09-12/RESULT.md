## 原始失败的离线复现

使用上一轮实际 SDK 响应中的检索参数，而非凭报告重构查询；对照使用上一轮 `tasks.json` 中的冻结语料。原请求位置、原始调用、文件 SHA256、完整候选及原文存于 [修改前回放](../../../output/retrieval-feedback-2026-09-12/before-replay.json) 和 [修改后回放](../../../output/retrieval-feedback-2026-09-12/after-replay.json)。这些回放没有远程调用，也没有自动改写查询。

以下每格为“返回候选数 / 正分匹配数 / 目标原文片段数”。最后一项按冻结目标原文与来源进行核对，只表示材料相关性，不等于任务完成。

| 原始请求 | 原过滤 | 同查询、去掉 section | 同查询、指定实际章节 |
|---|---:|---:|---:|
| `确认氨氯地平的用药信息是否准确。`；top_k=1；drug_name=氨氯地平；section=用药信息 | 0 / 0 / 0 | 1 / 0 / 1 | 药物相互作用：1 / 0 / 1 |
| `氨氯地平`；top_k=5；drug_name=氨氯地平；section=适应症 | 0 / 0 / 0 | 1 / 1 / 1 | 用法用量：1 / 1 / 1 |

第一条来自历史 B2 `14-B2-vp-conflict-003b/wire-005.json` 中实际执行的氨氯地平调用；同一响应里未执行的第二项克拉霉素调用没有算进复现。相关原文为“氨氯地平与克拉霉素合用可增加低血压风险，需监测血压。”第二条来自 B1 `01-B1-vp-missing-002a/wire-004.json`；相关原文为“氨氯地平常用起始剂量为每日一次5mg；剂量调整需监测血压。”这里只将合成原文作为软件测试资料。

结论分开记录：

- 第二条的对照支持过滤导致匹配证据丢失。同查询去过滤和改为实际章节均产生正分命中。
- 第一条去过滤后出现的是**零分候选**：旧精确检索把整个中文长句当作匹配项，却仍返回排序末尾的零分片段。过滤确实阻止了候选产生，但不能据此声称“只改章节就能匹配查询”。它同时涉及查询未匹配；新契约会如实返回 `no_match`。
- 这两个冻结任务里，“用药信息”和“适应症”均不是当前合法章节。不能把第二条冒称为“合法章节选错”的历史案例；这一类在独立合成对照中覆盖。

修改后同样三个条件的结果分别是：第一条 `invalid_filter / no_match / no_match`，候选均为 0；第二条 `invalid_filter / found / found`，候选为 `0 / 1 / 1`。只有模型另行提交较短查询，第一条才可能获得正分命中；服务端不会代填。

## 共用检索契约与计数

主要实现位于 [retrieval.py](../../../stage0/harness/retrieval.py)，通过 [default_tools.py](../../../stage0/harness/default_tools.py) 进入 B1 `rag_search` 和 B2 `acquire_evidence`，也进入正常产品 API 的工具执行路径。

- 复用当前 RAG 索引的 chunk 元数据，新增只读 `rag_catalog`。目录先按可信 principal 的 scope 筛选，再计算章节、药名、数量与内容版本；公共说明书仍可共享。目录最多返回 32 个章节，附总数、遗漏数、`next_offset`；合法但未列在首页的章节仍接受服务端验证。没有用全局固定 enum，也不要求模型猜内部分类。
- `section` 是可选的精确过滤。省略时搜索全部授权章节，`drug_name` 等其余过滤仍然生效。目录不是原文；B1 返回候选和证据 ID，引用前需 `read_evidence`；B2 返回完成权限及哈希校验后的有界原文页。
- 结构化状态区分 `invalid_filter`、`empty_filter_scope`、`no_match`、`retrieval_error`、`found`。另有 `invalid_query` 用于空查询和数值范围错误。参数类型仍经过原执行器 schema 校验；合法值验证在共享服务端执行。
- 反馈包含原查询、已应用过滤、无效字段、合法目录、语料版本、可访问及过滤后范围、是否真正执行搜索、候选数量、结果类型和截断信息。目录获取失败时标明不可用，不拿未知版本假充当前目录。
- 保留已有精确检索后备方式：使用相同查询、过滤和授权语料，不扩大范围。主检索故障但后备取得候选时，`found` 同时携带 `retrieval_degraded`、故障类别及 `deterministic_internal` 归因；后备也未取得候选则返回 `retrieval_error`，不能断言没有依据。这不是模型纠错。
- 返回候选再次按授权语料成员及内容核对；受 scope 限制的材料捕获为相应作用域的证据。其他作用域的章节、药名、数量和版本不会进入本作用域目录。元数据及搜索不复用旧缓存，以免目录更新后旧过滤继续被旧缓存接受。

[investigation.py](../../../stage0/investigation.py) 将实际执行搜索与工具尝试分开。无效过滤及空材料范围未执行搜索时不增加 `queries`；所有检索提案仍有工具审计、模型请求和回合计数。真正执行过的搜索逐次计数，修正章节后的相同查询也占一次有效搜索；搜索签名包含参数和语料版本。相同无效参数的重复仍进入既有无进展护栏。

最后一次有预算的搜索若找到候选，仍允许回读已取得的证据；预算耗尽后不能再增加搜索。B2 的内部搜索和读取没有算成模型额外规划，也没有重复增加模型工具尝试。

[agent.py](../../../stage0/agent.py) 和 [summary.py](../../../stage0/harness/summary.py) 保留下一次模型请求中的结构化结果，旧观察压缩后仍带状态、目录、范围与截断信息。候选文字的截断标记包含在原有 200 字上限内。模型可以自行去过滤、改章节、改查询或使用既有补问与部分交付能力；完成、安全和补问门槛没有放宽。
