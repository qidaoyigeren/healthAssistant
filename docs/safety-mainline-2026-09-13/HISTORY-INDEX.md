## 已被本轮删除脚本的原始结论

### 模型与规划（A0–A5 及其后续轮次）

- **A0 基线**：13 族 author-synthetic 开发集上，旧规划器 **0/13** 交付有界证据覆盖报告。
  入口 `agent_evals/run_eval.py` **保留**（默认验证入口调用它）。
- **A1–A2**：`investigation@1` + `evidence_review@1` 把同一开发集做到 **13/13**（replay 与
  真实本地工具两条路径）。引擎保留；本轮在其上新增 `safety_case@1` 契约。
- **A3–A4**：路由记录可核查依据、拒绝熔断、确定性双角色复核。全部保留。
- **A5 验收**：378 次测试、33 个模块通过；**3/3 任务产出、0/3 自主规划成功**。
  原始记录保留在 `closeout-2026-09-10/`。
- **planner-closeout-2026-09-11**：394 次测试、34 个模块；live k=3 队列
  **2/3 任务产出、0/3 自主规划成功、8/20 provider 响应**。
  → 结论：*稳定的开放式模型体验尚未被验收。* 本轮不作相反声明。
- **planner-protocol-v3-2026-09-11**：漏 `query` 的真根因是**不透明 `arguments`**；
  改为具名函数后真实模型自行填 `query`，参数拒绝 6→0。批次仍 1/3 未达门槛，
  瓶颈是**限流**而非模型能力。
- **latency L0–L1**：延迟度量落地；隐藏推理属**模型**而非网关（控制组证明）。
  产品端点据此切换；质量改为事后确认项。

### 取证与失败归因（2026-09-12 / 09-13）

- **evidence-loop-2026-09-12**：0/8 的根因在**代码**——重复检测默认关、只比上一步、
  缺口不写谁关得掉。修复后模型开始自主检索，但 `read_evidence` 仍 0 次、通过率仍 0/8。
- **retrieval-feedback-2026-09-12**：被拒报告根因是**疑问句被判成风险断言**（类别错误），
  修在检查器。A/B 实测 32/60 请求、门槛 0/6 未达。
- **tool-history-2026-09-13**：工具对话历史对照；有效反馈利用案例 1 个（n=1，不可配对）。
- **model-tool-controlled-2026-09-12**：受控对照实验，未改变默认臂。

  → 这几轮到本轮为止的总结论：**模型侧的开放式调查能力仍未被验收**；本轮因此
  不依赖它来保证安全——必要检查、结论与事项建立全部下沉为代码路径。

### 材料核对（product-upgrade / material-*）

- **P0–P6 与 live-acceptance**：材料工作流通过；严格 live 模型验收因 provider 超时
  与响应兜底**仍然失败**。保留 `docs/product-upgrade/`。
- **material-review-2026-09-13 / material-coverage-2026-09-13**：契约与状态模型、
  增量更新、基础覆盖下沉到运行器均已实施；690 测试全过、浏览器 15/15。
  **但交付恒为 partial、真实模型从不外部取证。**
- 本轮处置：材料能力**降为支持能力**，不再是产品中心；其引擎（`review/`）与
  运行核心（`ReviewRunner.advance`）**保留并复用**，只删除每轮一套的编排与验收脚本。

## 判据：什么留下、什么删掉

删掉的都是**入口**（脚本 / 夹具 / 一次性编排），且满足其一：

1. 只被历史文档引用，非文档代码里没有任何调用方；
2. 属于已结束的对照实验（P3 委派、model-tool、retrieval-feedback、tool-history）；
3. 被同功能的当前实现取代（每轮一套的浏览器验收、回放、打分、对账脚本）。

留下的都是**能力**：确定性引擎、记忆与依赖索引、证据库、任务与预算、材料核对核心，
以及默认验证入口 `scripts/verify-agent-closeout.py`——现在它还会跑主线产品验收，
并按类别分开报告。
